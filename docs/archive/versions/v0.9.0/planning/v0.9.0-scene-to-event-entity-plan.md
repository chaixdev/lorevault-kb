# v0.9.0: Scene → Event (Timeline) Implementation Plan

Date: August 21, 2025
Status: Planning
Context: Promote Scenes to first-class Events and build a skeleton timeline for chapter-level “so far” answering.

## Executive summary

We will represent Scenes as first-class Events and establish explicit temporal relationships between them to form a robust, queryable skeleton timeline. This unlocks chapter-level spoiler-gated narrative queries and sets the foundation for future temporal reasoning and Claims anchoring.

Key decisions

- Reingestion-only during development: no backfill/rollback tooling; wipe-and-reingest when needed.
- Dual labels: nodes are labeled :Event:Scene to preserve existing Chapter → HAS_SCENE → Scene → HAS_CHUNK → Chunk hierarchy.
- No OCCURS_IN edges; keep existing HAS_SCENE.
- Temporal edges: single relationship type TEMPORAL with properties.
- Naming: use temporalRelation (BEFORE, MEETS, OVERLAPS, DURING, STARTS, FINISHES, EQUALS) rather than Allen jargon.
- Certainty: Explicit | StronglyImplied | WeaklyImplied | Heuristic mapped to numeric weights.
- Edge evidence: rationale + optional offsets/chunkId live on the edge.
- Cross-chapter: add MEETS@Heuristic from last scene of chapter k to first of k+1; LLM upgrades when confident.
- Spoiler gating: enforced at chapter level (not scene).
- Flags (minimal): Flashback, ParallelPOV, Dream.

## Target state (graph model)

Nodes

- :Event:Scene
        - Semantic (Event) fields: eventType="SCENE", title, description, flags[]
        - Segmentation (Scene) fields: sceneIndex; startOffset/endOffset or firstChunkId/lastChunkId
        - Coordinates: carried via Chapter/Book structures; duplicate minimal fields only if convenient

Relationships

- (:Chapter)-[:HAS_SCENE]->(:Event:Scene)-[:HAS_CHUNK]->(:Chunk)
- (:Event)-[:TEMPORAL { temporalRelation, certainty, source, weight, rationale, evidenceStartOffset?, evidenceEndOffset?, evidenceChunkId? }]->(:Event)

Temporal edges contract

- Direction: earlier → later
- temporalRelation ∈ { BEFORE, MEETS, OVERLAPS, DURING, STARTS, FINISHES, EQUALS }
- certainty ∈ { Explicit, StronglyImplied, WeaklyImplied, Heuristic }
- source ∈ { CHAPTER_SEQUENCE, LLM_TEMPORAL, MANUAL }
- weight: numeric mapping of certainty (initial: 0.95, 0.8, 0.6, 0.5)
- rationale: short justification text; evidence* optional

0.8.3 — Dual-write ingestion (Scenes → Events)

Feature

- None public. On ingest, create :Event:Scene for each scene; link Chapter via existing HAS_SCENE and attach chunks.

Technical

- Update ingestion: after scene detection, persist matching Event nodes with sceneIndex and offsets/chunk range.
- Reingestion-only for existing content (wipe and reprocess).

Acceptance

- After reingestion, event count equals scene count per chapter.

Requirements (testable)

- Ingestion pipeline persists :Event:Scene for each detected scene with sceneIndex and either offsets or chunk range
- Chapter maintains existing HAS_SCENE relationships to the new Event:Scene nodes; HAS_CHUNK remains attached to Event
- Reingestion strategy documented; no backfill tooling required; dev scripts provided for wipe + reingest

Quality gates

- Integration test: ingest sample chapter → number of Events equals number of Scenes; Events linked to Chapter and Chunks
- Observability log includes counts of events and temporal links created (even if 0 for this patch)

0.8.4 — Skeleton timeline edges (default MEETS@Heuristic)

Feature

- Internal timeline service returns ordered Events per chapter (edges first, fallback sceneIndex).

Technical

- Create TEMPORAL edges Ei → Ej for consecutive scenes within chapter: MEETS@Heuristic, source=CHAPTER_SEQUENCE, rationale="chapter sequence".
- Cross-chapter: link chapter k last → chapter k+1 first similarly.
- Add basic cycle guard for precedence edges.

Acceptance

- Deterministic per-chapter and cross-adjacent-chapter ordering with or without edges (edges preferred, sceneIndex fallback).

Requirements (testable)

- For each chapter, consecutive Events are linked by TEMPORAL edges Ei→Ej with temporalRelation=MEETS, certainty=Heuristic, source=CHAPTER_SEQUENCE, weight=0.5, rationale="chapter sequence"
- Cross-chapter: last Event of chapter k → first Event of chapter k+1 with same default edge
- Cycle guard prevents creating BEFORE/MEETS edges that introduce cycles (fails-fast with log + skip)
- Ordering service produces ordered list for a chapter using edges-first, then sceneIndex as fallback

Quality gates

- Integration tests assert edge properties and ordering determinism for multi-chapter fixture
- ArchUnit: no adapters directly depend on web layer; service boundaries preserved

0.8.5 — LLM temporal upgrades + neighbors API (internal)

Feature

- Internal API to retrieve temporal neighbors with relation + certainty + rationale.

Technical

- LLM step (in-pipeline or background) examines consecutive pairs for explicit cues and upgrades edges (e.g., BEFORE, DURING, OVERLAPS) when confident; record rationale and evidence offsets.
- Idempotent promotion: never remove all links; retain MEETS if unsure.

Acceptance

- On curated chapters, some edges show upgraded temporalRelation with non-Heuristic certainty; neighbor API returns enriched relations.

Requirements (testable)

- LLM step can upgrade default MEETS@Heuristic edges to BEFORE/DURING/OVERLAPS/etc with certainty ∈ {Explicit, StronglyImplied, WeaklyImplied}
- Upgrades persist rationale and optional evidence offsets/chunkId; weight updated via mapping
- Idempotent promotion: when re-run, no duplicate edges; default MEETS retained if upgrade confidence < threshold
- Internal API: GET /api/timeline/events/{eventId}/neighbors returns prev/next neighbors with relation, certainty, weight, rationale, offsets

Quality gates

- Unit tests for upgrade rules and idempotency (≥3 cases: upgrade, no-upgrade, repeated-run)
- Controller slice test for neighbors API response schema

0.8.6 — Timeline query + GraphRAG NLQ (research)

Feature

- Timeline query: list ordered Events up to chapter N (spoiler gate).
- GraphRAG (research proposal): separate endpoint spec lives in research docs; implementation can follow after acceptance.

Technical

- Ordering across chapters by publication coordinates; within chapters by TEMPORAL edges first, sceneIndex fallback.
- Summarization over ordered Event descriptions/snippets; include evidence optionally.

Acceptance

- "What happened so far?" returns a coherent summary aligned with Event order; evidence included when requested.

Requirements (testable)

- GET /api/timeline/books/{bookId}/events?uptoChapter=N&includeEvidence=bool returns ordered Events respecting chapter spoiler gate
- GET /api/timeline/chapters/{chapterId}/events returns ordered Events (edges-first fallback-to-sceneIndex)
- Optional includeEvidence toggles inclusion of rationale and offsets in responses
- NLQ POC endpoint (path TBD in research) returns a textual summary using the ordered Event list; research-aligned contract documented

Quality gates

- Web layer tests for both endpoints including spoiler gate behavior and evidence toggle
- E2E smoke test: NLQ endpoint produces non-empty summary consistent with Event order for fixture data

## Implementation details

Model (illustrative)

```java
@Node({"Event", "Scene"})
public class EventNode {
        @Id
        private String eventId; // ULID/UUID

        // Semantic (Event)
        private String eventType; // "SCENE"
        private String title;
        private String description;
        private Set<String> flags; // Flashback, ParallelPOV, Dream

        // Segmentation (Scene)
        private Integer sceneIndex;
        private Integer startOffset; // optional
        private Integer endOffset;   // optional
        private String firstChunkId; // optional
        private String lastChunkId;  // optional
}

@RelationshipProperties
public class TemporalEdge {
        @TargetNode
        private EventNode later; // earlier (owner) -> later

        private String temporalRelation; // BEFORE|MEETS|OVERLAPS|DURING|STARTS|FINISHES|EQUALS
        private String certainty;        // Explicit|StronglyImplied|WeaklyImplied|Heuristic
        private String source;           // CHAPTER_SEQUENCE|LLM_TEMPORAL|MANUAL
        private double weight;           // mapped from certainty
        private String rationale;        // short justification
        private Integer evidenceStartOffset; // optional
        private Integer evidenceEndOffset;   // optional
        private String evidenceChunkId;      // optional
}
```

Ingestion changes

- After scene detection, persist matching :Event:Scene with segmentation fields and semantic summary/title.
- Create default MEETS@Heuristic TEMPORAL edges for consecutive scenes; cross-chapter link last→first.
- LLM upgrade step evaluates pairs for stronger relations and updates edge properties accordingly.

Timeline ordering (read-time)

- Within chapter: prefer TEMPORAL edges; fallback to sceneIndex for ties or gaps.
- Across chapters: concatenate by publication coordinates; cross-chapter edges confirm order when present.

## Risks and mitigations

- LLM misclassification → keep default MEETS edge; require evidence+rationale for upgrades.
- Cycles in precedence → guard when adding BEFORE/MEETS; validate acyclicity periodically.
- Data churn from reingestion → automation scripts for wipe/reingest; small datasets during dev.

## Handover and evolution

- Keep research proposals (e.g., GraphRAG endpoint) in research docs until handoff; do not edit official API spec until ready.
- Scene APIs remain as a facade over Events; deprecation can be evaluated post-0.9.0.
