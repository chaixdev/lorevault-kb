# Architecture Documentation Guidelines

**Status:** Active

## Core Rules

- architecture docs explain structure, rationale, and stakeholder concerns
- keep architecture documentation above implementation detail
- document trade-offs and constraints, not code snippets
- maintain consistency across viewpoints

## Keep Out Of Architecture Docs

- code examples
- framework configuration
- physical schema details
- implementation-level runbooks that belong elsewhere

## What Good Architecture Docs Should Do

- explain why the system is shaped the way it is
- clarify boundaries and relationships
- stay readable for their intended audience
- cross-link to lower-level specs, patterns, and data-model docs where needed
