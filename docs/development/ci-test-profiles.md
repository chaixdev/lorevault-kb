# CI Test Profiles and Commands

This document outlines the test execution profiles and commands available for local development and CI environments.

## Test Categories

### Unit Tests (Default)
- **Tag**: `@Tag("unit")`
- **Scope**: Fast, isolated tests for domain logic and services
- **Duration**: < 30 seconds
- **Command**: `mvn test`
- **Excludes**: Integration tests, architecture tests

### Integration Tests
- **Tag**: `@Tag("integration")`
- **Scope**: End-to-end tests with Testcontainers (Neo4j, external services)
- **Duration**: 2-5 minutes
- **Command**: `mvn verify -P integration-tests`
- **Includes**: Database interactions, external API calls, full Spring context

### Architecture Tests (Post-Refactor)
- **Tag**: `@Tag("architecture")` (currently excluded)
- **Scope**: ArchUnit rules enforcing ports & adapters boundaries
- **Duration**: < 10 seconds
- **Command**: `mvn test -P architecture-tests`
- **Status**: ⚠️ Currently disabled - 8 violations need post-refactor cleanup

## Maven Profiles

### Default Profile
```bash
# Run unit tests only (fast feedback loop)
mvn test
```

### Integration Tests Profile
```bash
# Run all tests including integration tests
mvn verify -P integration-tests
```

### Mutation Testing Profile
```bash
# Run PIT mutation testing (CI/nightly builds)
mvn test -P mutation-testing
```

## Quality Gates

### JaCoCo Coverage
- Reports are generated by default on `mvn test`, but the strict coverage gate is opt-in.
- **Gate thresholds (opt-in)**
	- Bundle: 85% instruction, 80% branches
	- Packages (service, domain, application): 90% instruction
- **Excludes**: Infrastructure adapters, configuration, main class
- **Commands**:
	- Default (reports, no gate):
		```bash
		mvn test
		```
	- Enforce gate (CI/explicit):
		```bash
		mvn verify -P coverage-gate
		```

### PIT Mutation Testing
- **Threshold**: 80% mutation score, 85% coverage
- **Target**: `com.lorevault.api.service.*`, `com.lorevault.api.domain.*`
- **Profile**: `mutation-testing` (opt-in for CI)
- **Duration**: 5-10 minutes

## CI Optimizations

### Testcontainers Reuse
- **File**: `src/test/resources/testcontainers.properties`
- **Setting**: `testcontainers.reuse.enable=true`
- **Benefit**: Faster integration test startup (containers persist between runs)

### Parallel Execution
- **Maven**: `forkCount=1C` (one fork per CPU core)
- **JUnit**: Classes run concurrently, methods sequentially (stable)
- **Configuration**: `src/test/resources/junit-platform.properties`

## Local Development Workflow

```bash
# 1. Fast feedback during development
mvn test

# 2. Pre-commit verification (includes integration)
mvn verify -P integration-tests

# 3. Weekly/nightly quality check
mvn test -P mutation-testing

# 3b. Coverage gate (enforce thresholds in CI or locally as needed)
mvn verify -P coverage-gate

# 4. Post-refactor architecture validation
mvn test -P architecture-tests
```

## Troubleshooting

### Test Failures
- **Unit tests fail**: Check service mocking and domain logic
- **Integration tests fail**: Verify Docker/Testcontainers setup
- **Coverage fails**: Add tests for uncovered branches
- **Architecture tests fail**: Address in post-refactor phase

### Performance Issues
- **Slow tests**: Enable Testcontainers reuse
- **CI timeouts**: Use appropriate profiles for CI stages
- **Memory issues**: Adjust Maven fork settings if needed
