# v0.9.0: Scene-to-Event Entity Promotion Implementation Plan

**Date:** August 21, 2025  
**Status:** Planning  
**Context:** Transform Scene entities into Event entities with temporal relationships

## Executive Summary

v0.9.0 focuses on promoting the current Scene model to a first-class Event entity with temporal relationship capabilities. This transformation will enable timeline construction, temporal querying, and lay the foundation for advanced knowledge graph features in later versions.

## Current State Analysis

### Existing Scene Model
- **SceneNode**: Basic scene storage with `sceneIndex`, `sceneText`, relationships to Chapter
- **Scene Detection Service**: AI-powered scene boundary detection using LLM
- **Scene Coordinates**: Integration with publication coordinate system
- **Chunk Integration**: Scenes contain multiple text chunks for processing

### Data Flow (Current)
```
Chapter Text → Scene Detection → SceneNode Creation → Chunk Generation → Embedding
```

## Proposed Event Model

### Core Event Entity Design

#### EventNode (New)
```java
@Node("Event")
public class EventNode {
    @Id
    private String eventId;
    
    // Core event properties
    private String eventType; // "SCENE", "CHAPTER_BOUNDARY", "BOOK_BOUNDARY"
    private String title;
    private String description;
    private String eventText; // Full text content
    
    // Temporal properties
    private Integer sequenceNumber; // Global sequence across all events
    private Instant estimatedTimestamp; // When event occurs in story time
    private Duration estimatedDuration; // How long event lasts
    
    // Source tracking
    private String sourceChapterId;
    private Integer sourceSceneIndex;
    
    // Publication coordinates (inherited from Scene)
    private String universe;
    private String series;
    private String bookTitle;
    private Integer bookNumber;
    private Integer chapterNumber;
    private Integer sceneIndex;
    
    // Relationships
    @Relationship(type = "OCCURS_IN")
    private ChapterNode chapter;
    
    @Relationship(type = "HAS_CHUNK")
    private Set<ChunkNode> chunks = new HashSet<>();
    
    @Relationship(type = "BEFORE", direction = OUTGOING)
    private Set<TemporalRelationship> beforeEvents = new HashSet<>();
    
    @Relationship(type = "AFTER", direction = INCOMING) 
    private Set<TemporalRelationship> afterEvents = new HashSet<>();
}
```

#### TemporalRelationship (New)
```java
@RelationshipProperties
public class TemporalRelationship {
    private String relationshipType; // "IMMEDIATELY_BEFORE", "SOMETIME_BEFORE", "CONCURRENT", "OVERLAPS"
    private String confidence; // "HIGH", "MEDIUM", "LOW"
    private String rationale; // Why this relationship exists
    private String source; // "SCENE_DETECTION", "CHAPTER_SEQUENCE", "MANUAL"
    
    // Allen Interval Relations support
    private String allenRelation; // "before", "meets", "overlaps", "during", "starts", "finishes", "equals"
}
```

### Migration Strategy

#### Phase 1: Parallel Model (0.9.0-alpha)
1. **Create Event entities alongside existing Scene entities**
2. **Implement Scene-to-Event transformation service**
3. **Maintain backward compatibility with existing Scene APIs**
4. **Add basic temporal relationship detection**

#### Phase 2: Event-First (0.9.0-beta) 
1. **Update ingestion pipeline to create Events directly**
2. **Implement timeline construction service**  
3. **Add temporal querying APIs**
4. **Deprecate Scene-based APIs (mark for removal in 1.0.0)**

#### Phase 3: Scene Removal (0.9.0-final)
1. **Remove Scene entities and related code**
2. **Update all references to use Event entities**
3. **Complete integration testing**

## Risk Assessment

### Technical Risks
- **Data Migration Complexity**: Scene → Event transformation may be complex
  - *Mitigation*: Extensive testing, rollback procedures, parallel model approach
- **Performance Impact**: Additional temporal relationship queries
  - *Mitigation*: Proper indexing, query optimization, performance testing
- **Backward Compatibility**: Maintaining Scene API compatibility
  - *Mitigation*: Facade pattern, comprehensive compatibility testing

### Timeline Risks
- **Scope Creep**: Temporal reasoning complexity could expand scope
  - *Mitigation*: Strict acceptance criteria, phased approach
- **Integration Complexity**: Event model touches many system components
  - *Mitigation*: Component-by-component integration, incremental testing
